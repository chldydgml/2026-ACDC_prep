# KotH / 거점 점령 플레이북

2026 예선 신규 형태. 공식 정의: **시스템을 점령 → 다른 팀 공격을 방어 → 점유 상태를 오래 유지할수록 고득점.**
최종 순위 = 문제풀이(Jeopardy) 점수 + KotH 점수 합산.

**Jeopardy와 다른 점**: Jeopardy = "한 번 풀어 Flag 제출하면 끝". KotH = **"점령 → 유지 → 방어 → 재탈환"의 시간 싸움.**
연결·정찰·API 통신은 공통이므로 `ctf-api-workflow`를 먼저 따르고, 유지 루프는 `templates/koth_loop.py`를 쓴다.

## 1. 점수 방식부터 파악 (가장 먼저)
플랫폼 명세에서 반드시 확인(10/30 접속테스트 때 미리 확인):
- **점유 판정 기준**: 무엇을 보고 "내가 점령 중"으로 치나 — 서비스 배너/응답의 내 마커? 특정 상태? 심어둔 파일?
- **틱 간격·점수**: 몇 초마다 채점하나, 점유 시 틱당 몇 점인가.
- **구조**: hill이 **공유 1개**인가 **팀별**인가. 패치/방어가 **허용되는 범위**는 어디까지인가.
- 점유 상태를 읽을 수 있는 **상태/점수 엔드포인트**가 있는가(모니터링 루프에 필요).

## 2. 거점 확보 (take)
- 취약점으로 접근 권한 획득 → **내 마커(표식)를 심거나** 요구 상태로 전환.
- AI 플랫폼형이면 `ai-platform-security`, 컨테이너/오케스트레이션이면 `docker-patterns`·`kubernetes-patterns` 연계.
- 재탈환에 바로 재사용할 수 있게 **점령 과정을 함수 하나(retake)로** 정리해 둔다.

## 3. 유지 · 재탈환 (hold / re-take)
- `templates/koth_loop.py`로 **상태 폴링 → 밀렸으면 즉시 재탈환** 루프를 돌린다.
- **틱 간격에 맞춘 얌전한 주기**로만(예: 틱이 15초면 ~15초 간격). 과도 요청·연속 난사 금지(규칙 + 비효율).
- 재탈환은 "정확한 exploit 1회 + 마커 재설치"로 짧고 확실하게. 무지성 반복이 아니라 밀렸을 때만.

## 4. 방어 · 하드닝 (defend) — KotH의 핵심 신규 능력
- 유지 시간을 늘리는 가장 좋은 방법은 **남이 못 들어오게 막는 것**(재탈환 빈도↓ = 점수↑).
- 내가 쓴 구멍 패치 · 심어둔 크레덴셜/마커 교체 · 서비스 가드레일 적용 — **단 내 접근 경로는 유지**(자기 발등 찍지 않기).
- 허용 범위 안에서만. (2025 본선 방어측 참고: 탐지·가드레일·자동 패치 / 공격측: 모델 탈취·데이터 중독.)

## 5. 점유 로그
- 보유/상실 시각을 타임스탬프로 기록 = **점수 근거 + 왜 밀렸는지 디버깅**. `koth_loop.py`가 `koth.events.jsonl`에 남긴다.

## 6. 역할 분담 (이 환경 = 2인 사용, 총 4인 팀)
- 여럿이면 나눠서: 한 명은 **점유·방어(유지)**, 한 명은 **재탈환·신규 공격**. 1인이면 **방어로 유지 시간을 늘려** 재탈환 부담을 줄이는 쪽으로.
- 다른 팀원 2명은 별도 환경 → 같은 hill을 중복 공격하지 않게 **대상/역할만 사전 합의**(팀 내 협업은 허용, 타 팀과 공유는 금지).

## 7. 규칙 (엄수)
- 공격 대상 = **제공된 격리 환경만**. 운영서버·점수판·관리자 기능·타 팀 기기/계정·외부 시스템 금지.
- **DoS/DDoS · 과도한 자동 요청 · 대량 스캔·퍼징 금지.** KotH의 주기 루프는 틱에 맞춘 소량이어야 한다.
- 점수·진행상황 조작(타 팀 정답 삭제, 문제파일 변조 등) 금지. 타 팀과 flag/풀이 공유 금지.
- 시각 기준 KST, 종료 시각 이전에 대회 서버에 접수된 것만 인정. 플랫폼 결함 발견 시 악용 말고 운영진 신고.
