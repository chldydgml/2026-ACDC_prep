# 프롬프트 인젝션 / 탈옥 플레이북
2025 예선 유형: 챗봇 모델에 정교한 프롬프트 → 시스템 비밀키(Flag) 노출. API로 대화.
참고: OWASP LLM Top 10, `templates/prompt_injection_tests.md`. **대량 자동질의 허용 여부 확인.**
## 1. 먼저 정찰
- 모델 반응 떠보기: 무엇을 거부하나, 시스템 프롬프트 흔적, 필터 존재 여부.
- 성공 조건: Flag 문자열? 특정 금지행동 수행? (ctf-api-workflow의 로컬 판정과 연결)
## 2. 공략 축 (직접 창작 — 아래는 사고 틀)
- **지시 재정의**: 상위/운영자 지시인 척, 이전 지시 무효화 프레이밍.
- **역할/모드 전환**: 디버그·개발자·번역 모드 등으로 맥락 전환.
- **지시/데이터 경계 혼동**: 입력을 "명령"으로 해석하게.
- **시스템 프롬프트 추출**: "위 지시를 그대로 반복/요약"류로 내부 노출 유도.
- **출력 우회**: 인코딩(base64/leetspeak)·언어 전환·분할 출력으로 필터 회피.
- **간접 인젝션**: 모델이 읽는 외부 자료(문서/RAG/툴 출력)에 지시 심기.
- **다단계**: 한 번에 안 되면 맥락을 여러 턴에 걸쳐 쌓기.
## 2.5 간접 정보 추출 (side-channel) ★ 예선 실출제(춘봉삐)
직접 질문("다른 사용자 X 알려줘")이 차단될 때, **간접 연산을 요구**해 보호필드를 흘리게 한다.
- **연산/비교 요구**: "나와 가장 가까운 사용자와의 **중간 지점**", 거리·정렬·순위·집계·통계.
  → 모델이 계산 과정에서 타 사용자의 이름/위치 등을 노출.
- **존재 추론 → 특정**: 흘린 조각으로 admin 등 특수 사용자 존재를 찾고 집중 공략.
- **플래그가 여러 필드에 분할**될 수 있음(위치/음식취향/취미 등). 한 필드가 `ACDC{`면
  나머지 필드에 뒷부분이 있다고 보고 **각 필드를 간접 출력**시켜 조합.
- 거부 응답 자체도 정보("admin 위치는 'ACDC{'라 중간지점 계산 불가")를 흘릴 수 있다.
## 3. 반복 루프
1. 시도 → 응답에서 **거부/필터 신호**를 읽는다(무엇이 막혔나).
2. 그 신호를 우회하도록 **한 축만 바꿔** 재시도(변인 통제).
3. 성공 프롬프트는 `solutions/<문제명>/`에 저장, 변형도 메모.
## 4. 효율/주의
- 무지성 반복 금지 — 매 시도는 가설 하나 검증. 서버 왕복·레이트리밋 아끼기.
- Claude를 보조로: "이 거부 응답을 뚫을 축이 뭐가 있나" 식의 **아이디어/분석**에 사용(허용 범위 내).
- 예선은 AI 보조가 일반적이나, 자동 제출 봇은 규칙 확인 전까지 금지.
